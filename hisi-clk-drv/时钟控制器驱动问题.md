## 二、初步分析排查：

    1、初步判断：
    	KASAN 检测到空指针解引用，与些同时发生了Oops。在 `__clk_get_hw` 函数中访问了一个NULL指针，最终导致 `Kernel panic - not 
    	syncing: Attempted to kill the idle task!`。
    
    2、根据错误信息分析调用链：
    _clk_get_hw() <—— clk_register_clkdev() <-——hickl_register() <-——hickl_clocks_init ()<—— hi3798mv100_clocks_init() 
    <—— of_clk_init() <—— time_init() <—— start_kernel()
    
    3、崩溃点：
    	 最后一条指令反汇编是   u2204@u2204:~$armdis e5940008
    						0:   e5940008        ldr     r0, [r4, #8]
    	“_clk_get_hw” 中读取地址 “0x00000009”，对应“r4 = 0x00000001”（即传入的 “clk” 指针值为 “1”，通常r0为第1个函参，它转
    	存r4）。
    
    4、查看源码：
    	grep -n -B5 'clk_register_clkdev(' ./clk-hisi.c
    		204-    clk = clk_register(NULL, &hihw->hw);
    		205-    if (IS_ERR_OR_NULL(clk)) {
    		206-            pr_err("%s: register clock fail.\n", __func__);
    		207-            return NULL;
    		208-    }
    		209:    clk_register_clkdev(clk, hihw->name, NULL);
    	在clk_register_clkdev()函数的前面加‘pr_err("Before clk_register_clkdev: clk = %p,PTR_ERR = %ld\n", 
    	clk,PTR_ERR(clk));’，
    	输出信息是：
    		[    0.000000] clk-hisi: Before clk_register_clkdev: clk = 81582cd8,PTR_ERR = -2124927784
    	clk = clk_register()返回值是有效的指针。但奇怪的是为什么到了clk_register_clkdev内部变成了”1“。
    

## 三、深入分析原因

    1、查阅Elixir：
    	在linux-5.2-rc1输入`clk_register`，找到`clk_register()`函数源码，注释里有“clk_register is the deprecated 
    	interface for populating the clock tree with new clock nodes. Use clk_hw_register() instead.”
    	同样的，在linux-5.1的最后一个版本里，`clk_register()`函数源码注释里没有这样的描述。
    
    2、故障根本原因：
    	老的 `clk_register()` + `of_clk_add_provider()` 组合在5.2版本以后的内核里已被标注为 deprecated，混用时 consumer 端 
    	`clk_get()` 可能因 provider 未正确暴露 `clk_hw` 而失败，且驱动卸载后 `clkdev` lookup 未被清理会导致 clkdev lookup 泄漏
    	（leak）；因此必须切到 `clk_hw_register()` + `of_clk_add_hw_provider()`，或更进一步用 `devm_clk_hw_register()` + 
    	`devm_of_clk_add_hw_provider()` 让框架自动回收**。
